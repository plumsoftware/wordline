# Соедини слова — кроссворды

Android/Jetpack Compose-игра по `soedini-slova-tz-assets-v1.1-complete.zip`. Продолжение реализации после первого среза: в исходники добавлены кампания, ежедневные режимы, метапрогресс, файлы, звук и реклама.

Исходное [ТЗ и полный пакет материалов v1.1](docs/spec/README.md) сохранены в проекте.

## Реализованные возможности

- 1000 основных и 365 ежедневных конечных кроссвордов, 434 авторские словарные записи. В contentVersion 3 исключены четыре слова по запросу пользователя; замены сохраняют идентификаторы и геометрию сеток. Старые сессии и импортируемые сохранения адаптируются без сброса баланса и пройденных уровней. Уровни не генерируются на телефоне; редакторская приёмка слов, сложности и темпа ещё впереди.
- Целевые/бонусные слова, пересечения, три вида подсказок, звёзды, бесплатные подсказки в повторе без повторной награды. Отдельное обучение с бесплатной буквой. Свайп с возвратом, проверка сегмента быстрого движения, ввод нажатием и клавиатурой.
- Room: профиль, сессии, лучшие результаты, журнал и совокупное состояние прогресса. Все денежные операции транзакционны, ключи наград уникальны. Миграция БД1→2 сохраняет прежние таблицы; destructive fallback отсутствует.
- Логическая дата без отката назад; календарь месяца, отдельная ежедневная сессия, подарки1…7, серия, три задания с автоматической выдачей готовых призов при смене даты,12достижений и личная тропа.
-10локаций/фонов/открыток, открытие глав, коллекция, оформление, статистика и история7дат. Открытки можно отправлять через FileProvider или сохранять через системный picker.
- Экспорт `.wordsave`, строгий импорт с предпросмотром, SHA-256 и каноническим JSON, проверка целостности модели, атомарная замена и новое поколение профиля. Перед заменой создаётся проверенная страховочная копия. Хранятся3последние внутренние копии; внешние файлы игра не удаляет. Настройки устройства при импорте сохраняются.
- Yandex Mobile Ads 8.6.0: демонстрационные rewarded/interstitial в debug, загрузка по запросу с затемнённым диалогом и ожиданием до 30 секунд. Первые три основных уровня без рекламы, далее межстраничная при переходе после уровней 5, 7, 9 и далее. Видео — по нажатию; награда и зелёная кнопка только после подтверждения SDK и сохранения операции. В QA реклама выключена. Нет баннера и рекламы при выходе. Debug-диагностика содержит 20 последних событий. Подробности и ограничения проверки — `docs/ads-flow-2026-11-22.md`.
-5оригинальных синтезированных эффектов и16-секундная музыкальная петля, отдельные переключатели музыки/эффектов/вибрации, обработка audio focus. Настройки контраста, крупных букв, уменьшенного движения и альтернативного ввода.

## Три магазина

В [app/build.gradle.kts](app/build.gradle.kts) созданы `rustore`, `googlePlay`, `huaweiAppGallery`, dimension `store`. В каждом `create(...)` рекламные ID задаются непосредственно строками в `buildConfigField`: `REWARDED_AD_UNIT_ID`, `LEVEL_COMPLETE_REWARDED_AD_UNIT_ID`, `INTERSTITIAL_AD_UNIT_ID`. Редактируйте значение прямо в нужном поле; таблица `storeAdUnits` и переопределения рекламных ID через Gradle properties не используются.

Для RuStore заданы блоки владельца: rewarded `R-M-20460787-2`, rewarded после уровня `R-M-20460787-3`, interstitial `R-M-20460787-1`. Для других магазинов ID пока не предоставлены. В каждом `create(flavor)` прямо в `buildConfigField` задаются также `STORE`, `SUPPORT_EMAIL`, `PRIVACY_URL`, `AUDIENCE` (`general` или `children`). Сведения издателя пока пустые. `ADS_ENABLED` задан прямым значением в каждом build type. Debug всегда использует `demo-rewarded-yandex`/`demo-interstitial-yandex`; release не подставляет их вместо настоящих ID. `validateReleaseInputs` блокирует release без сведений издателя. Ключ подписи в проект не добавлялся. Подготовка подписанного релиза и публикация требуют данных владельца и отдельной приёмки.

Build types: `debug`, `qa` с отключённой рекламой и `release` с полным R8/resource shrinking. Во всех вариантах сборки и магазинах applicationId — `ru.plumsoftware.wordline`, без суффиксов; namespace совпадает с ним.

## Контент и файлы

`tools/prepare_campaign.py` — воспроизводимый авторский конвейер1000+365, seed20261120; использует исходные определения и `tools/dictionary-ru.tsv`. `tools/content-editorial-report.json` описывает подготовленный объём и pending-редактуру. Инструмент запускался для создания контента, отдельный валидатор пока не запускался. Старый `prepare_content.py` оставлен как источник первых30фикстур; его прямой запуск заменяет пакет ранней версией, поэтому для текущего пакета используется именно `prepare_campaign.py`.

`tools/validate_content.py` подключён к `preBuild`; ему нужен Python3 на машине разработчика. Проверяются checksum, обе таблицы IDs, буквы, направления, связность, размеры, нежелательные примыкания, определения и бонусы. Runtime проверяет тот же класс инвариантов. `tools/prepare_audio.py` готовит собственные WAV без сторонних семплов. Реестр происхождения графики — `app/src/main/assets/content/asset-sources.json`.

Формат сохранения использует RFC8785/JCS на ограниченном домене: объекты, массивы, строки, bool/null и целые числа в безопасном диапазоне IEEE754. Дробные/экспоненциальные записи чисел отвергаются схемой. Строки не нормализуются. Дубликаты ключей, неправильный UTF-8, непарные суррогаты, глубина>20, файл>10МиБ и>100000логических записей запрещены. Контрольная сумма обнаруживает порчу, но не защищает от намеренного редактирования/отката офлайн-снимка.
